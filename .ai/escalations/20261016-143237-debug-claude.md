**Root cause:** the dossier's minimum height forces the whole row to overflow. Stale scripts are not the problem.

**Evidence**
- The log prints `image_min=(680.0, 320.0)`, so the edited `garage.gd` is the one running. The image panel is 508 tall only because it has `SIZE_EXPAND_FILL` (`garage.gd:127`). It absorbs whatever height `content` is given, so lowering its minimum from 440 to 320 changes nothing. Moving metadata out of the image and the 10→8 gap change did nothing for the same reason.
- The dossier is `y=206, h=722`, so it ends at 928. The stage's `nav` row also ends at 928 (`next` is `894 + 34`). The stage is stretched to match the taller dossier, so the next/previous row sits at the bottom of the overflowing row.
- The page area ends at `900 - 28 = 872`. The dossier needs `206 + 722 = 928`, so it overflows by about 56 px. The VBox page then runs past the viewport, because Control minimum sizes win over the available space.
- In the log's numbers, the roster's last row (`840 + 40 = 880`) and IGNITE (`816 + 60 = 876`) are inside the 900 viewport. The only failing controls are `next` (bottom 928) and presumably `prev`, both on the nav row at 894–928. The test's `encloses` check is correct. The dossier's own minimum is the fixed height being driven, not the image.
- The dossier minimum is the sum of fixed-size items in `_build_dossier` (`garage.gd:194-251`). These include the 46pt name label, the 54 px description, the four stat columns, the VIEW 3D button, the 38 px CPU panel, the callsign label and `LineEdit`, the 16 px validation label, the 60 px IGNITE button, and the hints label. The `separation` of 8 is applied between every child.
- The top of the page is also tall: a 76pt title, three 18 px page gaps, and 28 px margins above the content row.

**Smallest fix:** cut at least 56 px (the patch below saves about 70 px) from the chrome above the content row and from the dossier. Don't touch the image.

```diff
--- a/godot/scripts/garage.gd
+++ b/godot/scripts/garage.gd
@@ _build_interface
-	margin.add_theme_constant_override("margin_top", 28)
-	margin.add_theme_constant_override("margin_bottom", 28)
+	margin.add_theme_constant_override("margin_top", 16)
+	margin.add_theme_constant_override("margin_bottom", 16)
@@
-	page.add_theme_constant_override("separation", 18)
+	page.add_theme_constant_override("separation", 10)
@@
-	var title := _label("WHIPLASH SHIFT", 76, INK)
+	var title := _label("WHIPLASH SHIFT", 56, INK)
@@ _build_dossier
-	margin.add_theme_constant_override("margin_top", 26)
-	margin.add_theme_constant_override("margin_bottom", 22)
+	margin.add_theme_constant_override("margin_top", 18)
+	margin.add_theme_constant_override("margin_bottom", 14)
-	_name_label = _label("", 46, INK)
+	_name_label = _label("", 38, INK)
```

Estimated savings:

| Change | Saves |
|---|---|
| Page margins 28→16, top and bottom | ~24 px |
| Page separation 18→10, three gaps | ~24 px |
| Title 76→56 | ~24 px |
| Dossier margins 26/22→18/14 | ~16 px |
| Name label 46→38 | ~10 px |

That is about 98 px against the 56 px needed. If the margins and separation changes alone are enough, drop the title and name-size edits to keep the look.

**Verify**
1. Run `ak-test`. The "All named vehicle and ignition buttons fit the garage" check should pass.
2. The `LAYOUT_DEBUG` line, if it still prints, should show the dossier bottom at 872 or less.
3. The test only waits 2 process frames. If it still fails by a few pixels, add a third frame, since container sort is deferred.

5. Run the visual QA scene, using `ak-look` rather than loading screenshots yourself.

**Fallback:** if you want a layout that survives future additions, wrap the dossier `box` in a `ScrollContainer` with horizontal scroll disabled. Its minimum height is then ignored and the row can no longer overflow. The cost is a scrollbar on small windows, and the IGNITE button could then scroll out of view, which I'd avoid.
