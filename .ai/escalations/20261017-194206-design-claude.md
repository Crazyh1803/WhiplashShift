**Recommendation:** add one virtual getter to the shared adapter, and have Boilerfang supply its radii through the catalog. Blackjack already does this (`blackjack_blueprint_vehicle.gd:19-20`).

```gdscript
# deadbolt_blueprint_vehicle.gd
func _display_radius(end: String) -> float:
    return float(_visual_config.get("display_radius", DISPLAY_RADIUS).get(end, DISPLAY_RADIUS[end]))
```

Line 74 then calls `_display_radius(wheel.end)`. Deadbolt, Nightshift and Ramjet have no `display_radius` key in their catalog entries, so they keep .40/.43 exactly. Don't add a `boilerfang_blueprint_vehicle.gd` override unless it needs other behavior; catalog data is enough.

**Tradeoff:** the catalog becomes a second place that knows about wheel size. The one alternative worth considering is a Boilerfang subclass overriding `_display_radius`. That keeps the catalog clean but adds a file for a single number.

**Risks:**
1. **The adapter offsets the wheel, it doesn't scale it** (`:72-76`, unlike Blackjack). The catalog radius only sets the hub height. If it doesn't match the radius of the tire mesh in the GLB, the tires will float or sink. Measure the value from the GLB; don't take it from the reference image.
2. **Mesh naming:**
   - Line 53 assigns `Wheel_Coupe_*` to end A and every other `Wheel_*` mesh to end B.
   - Each side is picked by the sign of x, so a mesh at x≈0 is ambiguous.
   - `find_children("Wheel_*")` searches recursively, and `_configure_imported_meshes` hides every `Wheel_*` mesh. The flywheel, belt and any of their children must avoid the `Wheel_` prefix.
3. **Large display tire vs. a .40 physical tire:** under suspension compression, the visual tire can pass through the arches or body.
4. **The garage preview height is hardcoded:** `configure_static_preview` sets `y=0.62`, which may not suit Boilerfang's larger tires.
5. **Scope:** the flywheel stays static. Don't add belt animation or a fifth wheel to this branch.

**Tests worth adding:**
1. **Regression:** keep `nightshift_blueprint_tests.gd:78` and `consolidation_tests.gd:72` (the `-0.8 + .40/.43` checks). Add Ramjet to the same check if it isn't covered.
2. **Boilerfang ground contact:** for every wheel, `ModularWheelVisual` global y minus `_display_radius(end)` is under 5mm, both frozen in the garage and after settling in a race.
3. **Radius matches the art:** each end's catalog radius equals the tire mesh's AABB half-height within 5mm.
4. **Physics unchanged:** `wheel.radius`, hardpoints, collider shape, mass and drive equal the tuning values, compared against a snapshot.
5. **Mechanism:** `Prop_*` meshes exist and are visible. None is inside a wheel assembly, and each assembly holds only its own end's `Wheel_*` parts.
6. **No missing hubs:** no "missing the tire hub" error is logged.
