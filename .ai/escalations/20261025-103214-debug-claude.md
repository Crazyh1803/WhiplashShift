**Assessment of the convergence fix: correct, with one small improvement worth making.**

I read `_emit` and `_target` (`race_items.gd:337-447`) and did not run anything.

**What holds up**
- The muzzle position, the `_ray(origin, nozzle)` wall check (line 349) and the grenade lob are untouched. Grenades are excluded by `id != "grenades"` on line 353.
- `_target(index, id != "homing")` reuses the existing eligibility filter:
  - distance of 7 m or more,
  - within 60° of `_fire_direction`,
  - within 2 m of the lane when predicted,
  - not blocked by smoke,
  - line of sight confirmed by `_ray` hitting that car's collider.
- Convergence therefore only happens when a shot was already valid, so it can't turn a legitimate non-shot into a shot or aim through walls.
- Machine-gun jitter is applied after the convergence (lines 355-357), so spread is preserved.
- The `_target` filter works from the car's origin (`global_position + UP*0.35`), not the muzzle. Convergence aims from the muzzle, so the direction can differ by up to about 1 m of height. Because of the 2 m lane tolerance, this is harmless.

**Weakness: it aims at the target's current position.**
- Line 354 aims at `cars[t].global_position`, but eligibility on line 438 already uses a lead prediction, `linear_velocity * (distance / 105)`.
- Rocket speed is unknown to me, but if it is about 105, a target 140 m away that moves 2 m sideways between the two positions would still be hit or missed by that margin.
- A fast crossing target can therefore pass the filter and still be missed.
- Minimal fix: aim at the same predicted point the filter used.

```diff
     var aim_target := _target(index, id != "homing")
     if aim_target >= 0 and id != "grenades":
-        direction = (cars[aim_target].global_position + Vector3.UP * 0.35 - origin).normalized()
+        var aim_point: Vector3 = cars[aim_target].global_position + Vector3.UP * 0.35
+        aim_point += cars[aim_target].linear_velocity * (aim_point.distance_to(origin) / maxf(float(data["speed"]), 1.0))
+        direction = (aim_point - origin).normalized()
```

Using `data["speed"]` for the lead time is more accurate than the hard-coded 105. If you want a smaller diff, leave line 354 as is. The lane check already caps the error at about 2 m, which is within a car hull, so the prediction is optional.

**Secondary risk: homing.** `straight` is false for homing, so any car within 60° and line of sight gets the convergence aim. Homing then steers anyway, so this is fine and arguably better than before.

**Blackjack baseline mismatch: production isn't affected, so fix the test, not the code.**
- The y+1.03 versus y+0.35 gap is the roof mount height compared with the hull's mid-height. A shot fired from roof height along a level `_fire_direction` can pass over low collision hulls. The convergence fix does cover that.
- Production weapon mounts hold only visual meshes, so there is no mount collision geometry to mismatch.
- Hitting depends only on the vehicle's own collider.
- A test that spawns Blackjack with the default customization and expects the old y+0.35 muzzle height is asserting a stale baseline. Update it to expect the roof muzzle plus convergence, which is what the new attachment tests are doing.
- Don't add collision to the mounts. It would affect `_ray` self-hits and vehicle physics, and `_ray(..., index)` only excludes the owner car, not its mount bodies.
