**Recommendation: one builder module that imports the workshop as a library, holds each asset's state in its own object, and writes the manifest once; and one validator that wraps the workshop checks with an explicit config.**

**Builder (`build_city_neighborhood.py`)**
- Change the workshop's last line `main()` to `if __name__ == "__main__": main()`. Keep the `def main():` text as it is: `check_habitation_primitives.py:13` cuts the file at the string `"\ndef main():"` and execs everything before it.
- Load the workshop with `importlib.util.spec_from_file_location` using an explicit path. Don't rely on `sys.path`. `ak-blender` and `-I` both drop the script's directory from the path.
- Never use the module globals `ASSET_ID`, `OFFSET`, `TRI_CAP` or `PBOX`. Write a local `finalize_asset(aid, kit, mats, coll) -> (ob, offset)` that returns its offset instead of writing `OFFSET[:]`. Write `dp(offset, x,y,z)` and `to_godot(offset, x,y,z) = (-x+ox, z+oz, -(y+oy))` in the same way. `dp` at `:1949` and the setback at `:2021` read whatever the last `finalize` left behind, so the second building would silently get the first one's offset.
- Give each asset a spec: `id`, `parts` (list of functions), `facade_y`, design-space `review_targets`, shots, `functional_identity`. A depot module only has to add one spec.
- Call `make_materials()` exactly once per Blender session. A second call produces `steel.001` and similar, which fails the semantic name check.
- Export every GLB before calling `wire_vertex_colors()`. It changes the shared materials, so anything exported after it gets the multiply node.
- Use a fresh `Kit()` per asset. Seed with `random.Random(f"{aid}:{fn.__name__}")`, not just `fn.__name__` (`:1753`), so similar parts don't come out identical across buildings.
- `wear_tint` depends only on design-space position (`:176`). Buildings laid out around the same origin get matching grime. Add a per-asset phase as a Kit attribute that defaults to 0, so the workshop's output bytes don't change.
- Delete or hide the previous building's objects before rendering the next one. Otherwise two buildings at the origin overlap in the studio views.
- Check the render scale (0.25–2.0) before `read_factory_settings` runs.

**Manifest**
- Write `neighborhood_manifest.json` from the asset specs in one atomic write (temp file, then `os.replace`).
- Depot pass: either rebuild all three, or have the depot module load the manifest, replace or add only its own id, and write it back. Never create a second manifest file.
- Compute `review_targets` with `to_godot(offset, …)` after finalize. Never type Godot coordinates in by hand.

**Validator (`validate_city_neighborhood.py`)**
- Load `validate_habitation_workshop.py` by path as well, since `test_season.py:30` runs validators with `-I`.
- Its `check_glb` uses the module's `TRI_CAP=30000` (`:157`) and appends to the shared `errors` list. Set `vw.TRI_CAP = 35000` before calling it, take `len(vw.errors)` before and after for each asset, and run it in the separate process the season runner already starts. Don't edit the workshop validator.
- Neighborhood-level checks:
  - `EXPECTED_IDS` is an exact set and needs a deliberate edit for the depot. It's only satisfied when the manifest ids, the GLBs on disk in `neighborhood/` and the expected set all match. Also reject duplicate ids.
  - `glb` must equal `id + ".glb"`. Reject it if it contains `/`, `\`, `..` or a drive prefix, and confirm `realpath` stays inside the manifest's directory.
  - Required keys: `review_targets`, `lod_strategy`, `budget_note`, `functional_identity`.
  - Each target is three finite numbers inside the AABB plus a 3 m margin, with y ≥ 0.
  - At least 3 of the 8 semantic surfaces are used, and at least one glow is used.
  - The approved workshop and kit GLBs match pinned SHA-256 hashes, so a rebuild that changes them fails.
- `read_glb` doesn't check chunk lengths against the file size: a truncated chunk slice is silently shorter. Add a length check in the wrapper.

**Godot capture**
- Drive the script from the manifest: loop over assets, read `review_targets`, and frame shots from them, not from the AABB fractions in `habitation_visual_qa.gd:123-156`.
- Keep the `vertex_color_use_as_albedo` override (`:60`), applied per surface.
- Fail the run if any target is missing.

**Main tradeoff:** two indirections (path-loaded imports and per-asset objects) instead of copying the helpers. In return there's a single source for the Kit, winding fixes and export, and the workshop stays byte-for-byte unchanged.

**Alternative worth considering:** run one Blender process per asset (`--asset <id>`), with a merge step that writes the manifest. That gets rid of the shared-material and global-state problems entirely, but costs a merge step and more process starts.

**Risks to existing systems:**
- The `main()` guard must keep the workshop rebuild identical. Check it by rebuilding and comparing the SHA-256.
- Don't remove `validate_habitation_workshop.py` from the runner list in `test_season.py:29`; add the new validator next to it.
