## Recommended design: the roadside detail layer

The core is one shared check that keeps every generic building out of the roadside band. Everything else is added on top of that: overlays on the existing landmarks, boarded versions of existing frontage families, and a separate vignette module. All of it is measured against its own budget instead of being squeezed into the full 320k.

### 1. Layering rule (code only, do this first)
- **The gap:**
  - In converted mode, legacy `_towers` still draws bodies in quarters 2–4 at 11–19 m from the rail edge (`city_scenery.gd:267,272`).
  - `_service_decks` builds generic 6 m blocks at about 15 m (`:322`).
  - The backdrop rows start at 14–22 m and 10–16 m (`:441,443`).
  - All of these sit in the same band as the frontages, which are set back 9.5 m (`city_realism_layout.gd:81`).
- **The helper:** add `CityScenery.GENERIC_SETBACK` and `static func generic_clear(bounds, course) -> bool`. It runs `road_clearance` on the whole merged AABB, so it checks the full footprint, not the centre or the row label. Use it in `_backdrop_accept` and in `_accept` for generic tower and deck parts.
- **Setting the value:** derive it, don't guess it. Use the deepest far-edge clearance of the realism reservations plus 3 m, which is probably about 24–28 m. A test then asserts the constant is at least that measured value.
- **Converted city:** keep every legacy `_towers` RNG draw but set `emit_geometry=false`, so the skyline and crown stay deterministic. Skip `_service_decks` geometry the same way.
- **Backdrop rows:** remap the gap after the RNG draw (`gap = GENERIC_SETBACK + (gap - row[0])`). The stream stays identical; only positions shift.
- **Visual hierarchy, in `city_backdrop.gdshader` only:** lower the value, desaturate, remove window emission and add a slight distance haze. The detailed layer then reads as the foreground.
- **Hashes:** the backdrop geometry hash changes on purpose. Re-baseline it in its own commit. The frontage hash and the 66 frontages / 2 actor pairs must stay byte-identical.

### 2. Asset contracts (Claude via headless `ak-blender`, shared PBR library only)
| Asset | Contract |
|---|---|
| Landmark overlays (`pump_citadel`, `exchange_hall`, `relay_tower` if it's the column) | Separate GLB placed with the `placements` transform. The CityKit mesh is unchanged, so the silhouette stays. A `material_override` gives it library PBR. Overlay stays inside the local AABB grown 1.5 m and never moves the road-facing face. ≤25k tris and ≤3 surfaces each |
| Boarded variants of 2 frontage families | Footprint and bounds equal the source within 0.05 m. Same materials plus one plywood material. ≤ source tris +10%. The layout swaps the family ID at fixed slots, so the frontage count and actor pairs are unchanged |
| Camp cluster (tarp lean-to, bedrolls, bags, cart, cardboard) | One cluster ≤6k tris, one atlas material, ≤4 m × 3 m |
| Barrel fire | Barrel ≤800 tris. Flame is a procedural shader on crossed quads. Smoke is ≤24 particles with a fixed `visibility_aabb`. It gets an OmniLight only if `lights < MAX_LIGHTS`; otherwise it is emissive only |
| Roadside towers (last, can be cut) | Podium is an existing frontage family. The shaft is MultiMesh-stacked: a detailed lower-floor module ≤2.5k tris, a shader-windowed upper module ≤400 tris, and 2–3 crown variants ≤6k. Shaft set back at least 6 m behind the podium face |

Each Blender script in `.ai/blender/` must print `AK:` lines for tris, surfaces, bounds and material paths. Output goes to `assets/generated/city/...`, never `assets/final`.

### 3. Files
- `city_scenery.gd`: the setback helper, legacy suppression and the backdrop remap.
- `city_district.gd`: the landmark overlay and material override. Landmark slots stay unchanged.
- `city_realism_layout.gd`:
  - boarded families;
  - a `tower` role in a few slots;
  - an `ADDON_NEAR_BUDGET`/`ADDON_SURFACES` line in `_fits_visible`, which samples add-on groups separately (`:327-343`).
- New `city_vignettes.gd`: places camps and barrels with its own RNG seed. It only uses lots that infill left empty, off the road with clearance ≥ `ROAD_CLEARANCE + 2`, and never touches solids, reservations or actor lanes.
- New `shaders/barrel_fire.gdshader`.

### Budget (main tradeoff)
The 320k / 160 limits are saturated. **Recommendation:** leave them alone and add a separate, measured add-on cap. Start at 100k visible and 20 surfaces, and lower it to whatever is actually measured. Report the combined peak per quarter and check frame time on Vulkan against the same camera positions on f68b7e0. **Alternative:** stay inside 320k by giving up about 6–8 frontages for towers. That breaks the retention goal, so use it only if the frame-time capture fails.

### Focused checks (no full CPU suite)
1. **Layering:** every backdrop record and every emitted generic part passes `generic_clear`, and backdrop counts per quarter side stay ≥ `BACKDROP_MIN_PER_QUARTER_SIDE`.
2. **Frontages:** 66 frontages, 2 actor pairs and the frontage hash are unchanged.
3. **Source immutability:** a SHA list of the existing catalogue GLBs, CityKit and PBR library files.
4. **Asset contracts:** tris, surfaces, material paths and boarded-variant bounds equality.
5. **Vignettes:** clearance, no overlaps, effect AABBs inside their lot, total lights ≤12.
6. **Budget meta:** base and add-on peaks per quarter.
7. **Fallback:** without the new GLBs and without CityKit, the scene builds with no errors and the add-ons are simply absent.

### Captures
Use a fixed list of camera positions, all at 1.5 m road height: 4 per quarter, plus both landmarks, the tower fronts and each vignette. Capture them from the same list on the base and the branch.

### Delegation order (one at a time)
1. Layering, code only.
2. Boarded variants plus camp and barrel props.
3. Landmark overlays.
4. Towers.

### Risks
- **Lights:** the frontage block's lights already count toward the 12 (`city_scenery.gd:42`), so barrel lights may get none.
- **Determinism:** remapping the backdrop must not reorder RNG calls.
- **Boarded variants** whose bounds drift will move actor-pair lanes.
- **Particles** can cost more than their triangle count in the Vulkan frame.
