**Recommendation: don't override `_update_axle_visuals` or hide meshes by hand. Use the embedded-wheels path that already exists, plus one no-op override.**

1. In the `helix` entry of `vehicle_catalog.gd:114-120`, add `"embedded_wheels": true`. Helix has no `wheel_styles` (the default is `{}` at `vehicle_catalog.gd:179`), so `_wheel_style_embedded()` (`vehicle.gd:564-567`) returns true. The base class then handles every case itself:
   - `wheel.visible = false` when wheels are built and on every refresh (`vehicle.gd:340`, `vehicle.gd:350`). This hides the whole Wheel node, including the primitive `_visual` that `set_visual_scene` recreates on each `apply_customization`.
   - `_axle_root.visible = false` when axles are built and on every update (`vehicle.gd:418`, `vehicle.gd:472`).
   - The visual middle bogie is suppressed (`vehicle.gd:361-362`).
2. In `helix_blueprint_vehicle.gd`, override `_install_authored_wheels()` with `pass`. Without it, the Deadbolt adapter finds no `Wheel_*` tire hubs and calls `push_error` four times on every build and refresh (`deadbolt_blueprint_vehicle.gd:64-66`). With no `ModularWheelVisual`, Deadbolt's `_update_axle_visuals` skips each axle at line 107, so it is harmless.

**Why this beats the proposal**
- **Lifecycle:** the base re-sets `_axle_root.visible` on every `_update_axle_visuals` call, and `_build_axles` frees and rebuilds the root. A "super, then hide" override has to win that race on every call path: `_ready`, `apply_vehicle_spec`, `apply_customization` and the per-frame update. Hiding primitive wheel visuals inside `_install_authored_wheels` is fragile in the same way, because `set_visual_scene` brings them back on every refresh. A node-level flag avoids the race entirely.
- **Physics:** `wheel.gd` has no visibility coupling (no `visible` references), so hiding the wheels leaves the raycasts unchanged. With `collision_boxes: []`, collision falls back to the tuning box (`vehicle.gd:305-309`), and mass and inertia come from tuning (`vehicle.gd:280-292`). Nothing in this change touches forces.
- **Code size:** about 3 lines plus a test, against two overrides that copy base logic.

**Main tradeoff:** embedded mode hides all wheel visuals at once. If you later want the tracks to animate with suspension, you'll need a real adapter hook. Until then the tracks sit rigid on the body and may float or clip by up to the suspension travel under compression, so test "grounded at rest" with a tolerance.

**The one alternative worth considering:** the proposed override pair, but only if you need per-wheel track motion now. If you take that route, hide through `wheel.visible`, not individual meshes, and still route through `_wheel_style_embedded` so the base stays consistent.

**Risks to watch**
- **Customization:** if anyone adds `wheel_styles` to Helix with `"embedded": false`, the physical wheels reappear, and garage/session would expose the option (`garage.gd:468-472`, `game_session.gd:58-59`). Add a test that Helix has no wheel styles, or that every style is embedded.
- **Mesh naming:** `_configure_imported_meshes` hides any node whose name starts with `Wheel_` (`deadbolt_blueprint_vehicle.gd:10`). `Prop_Track_*` is safe, but have the GLB validation reject any `Wheel_*` names.
- **Paint:** this only works if the GLB material `resource_name`s exactly match `Helix_Paint`, `Helix_Secondary` and `Helix_Stripe`. Test that recolouring the palette changes the override materials.
- **Preview:** `configure_static_preview` sets y to 0.62 (`deadbolt_blueprint_vehicle.gd:96`), which matches the -0.62 offset. Ground z0 must hold at source scale (about 5 m overall).
- **Look:** the front contact patches sit under the wheel-less nose, so it reads as hovering. That's intended, but give `ak-look` an acceptance criterion for it.

**Helix tests**
- 4 wheels; positions, radius, mass, inertia and collision shapes identical to a baseline Vehicle with the same tuning.
- Every `wheel.visible` is false, and stays false after `apply_customization`.
- `AxleVisuals` and `VisualMiddleBogie` are hidden.
- `Prop_Track_*` meshes are visible, and their lowest point is within tolerance of y=0 at rest.
- No `push_error` output.
- Player and CPU construction both go through `VehicleFactory`.
- A physics parity step: N frames, same input, compare transforms against Deadbolt.
