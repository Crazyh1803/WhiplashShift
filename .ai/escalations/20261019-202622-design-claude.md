The plan holds up. Apply oil as its own grip factor that is recomputed every tick. That way cleanup can't be missed.

**1. Oil gets its own field and must not touch `grip_multiplier`.**
`grip_multiplier` is the vehicle's spec stat, set at `vehicle.gd:269`. `cpu_driver.gd:207,260` and `course_cues.gd:120,126` also read it, and `racecraft_tests.gd:248-270` checks that it never changes. Changing it would wreck CPU braking plans and cue colours, and if a restore were ever skipped the car would stay slow on grip permanently. So:
- Add a new field: `var item_grip_scale := 1.0  ## RaceItems-owned, 1.0 = no effect`.
- At `vehicle.gd:766`, multiply by `clampf(item_grip_scale, OIL_MIN, 1.0)`. The clamp inside Vehicle is the hard bound, so even a bad value can't make the car undriveable.
- Leave the CPU and cue planners blind to it. Oil should catch everyone out the same way, and the terrain surface (`Surfaces.GRIP[sid]`) still decides the rest of the grip.

**2. Recompute the scale every tick instead of applying and restoring it.**
RaceItems keeps `slick: Array[float]`, the seconds of oil left per racer. At the end of every `tick()`, for each car: `cars[i].item_grip_scale = OIL_SCALE if available(i) and slick[i] > 0 and shield[i] <= 0 else 1.0`. Finish, retirement and freeze then fix themselves through `available()`.
- Explicit resets to 1.0 are only needed in four places:
  - `reset()`, which covers retry (`proving_ground.gd:239`).
  - `reset_racer()`, which covers recovery.
  - The early return when the race isn't RACING (`race_items.gd:98`).
  - A new `_exit_tree()`, which covers the scene change at `proving_ground.gd:348`.
- Put all of these on one `_clear_world()` helper that frees shots, hazards and effects and resets the grip scale.

**3. Items:**
- **Catalog:** a separate `item_catalog.gd` holding a const Dictionary keyed by an int enum, with weights, durations and cadence. Rolls go through an injected `RandomNumberGenerator`, so tests can set the seed and check the 1% homing boundary.
- **Timed emission:** decrement an accumulator and use `while acc <= 0 and n < 2: emit; acc += cadence`. The cap of 2 stops one long frame from producing a burst.
- **Grenade:** goes into the existing `shots` list as `kind = GRENADE`, using the same swept `_ray` with gravity added to the velocity. It explodes on a hit or when the fuse runs out. For the blast, loop over `cars` (8 at most) and apply a hit if a car is within the radius and a `_ray` from the blast centre reaches it. That keeps scenery blocking the blast. Don't use `intersect_shape`: the plain loop is deterministic and cheaper.
- **Homing missile:**
  - Lock the target when it's fired: the nearest available racer ahead, using `_same_section`. Never pick a new target.
  - Turn only in the horizontal plane, limited to `TURN_RATE * delta` per tick, and keep using the swept ray every step so it can't tunnel through walls.
  - Limit its lifetime. If the target becomes unavailable or shielded, it flies straight.
- **Shield:** a separate `shield` timer. Every hit check becomes `protection[i] <= 0 and shield[i] <= 0`.
- **Smoke and oil hazards:** a new `hazards` list with a global cap of about 24, dropping the oldest first. Oil entry is a 2D distance check against the swept segment from `previous_positions`, the same way pickups work. Keep smoke visual-only, plus blocking CPU attack decisions. Don't let it touch steering.

**Main tradeoff:** a single per-car scale means a whole-car slide, not per-wheel slip when only some wheels are on the oil. That's simpler and deterministic, but less physical. The alternative worth considering is putting the per-wheel oil check inside `_integrate_forces` against the wheel contact points. It's more realistic, but it gives Vehicle knowledge of item geometry, which goes against the header rule at `race_items.gd:1`.

**Risks:**
- `tick()` runs from `_process` while `_integrate_forces` runs on physics. A float write is safe, but one frame of lag is possible. Tests should check the value after a tick, not in the same frame.
- More parallel arrays means `reset()` and `setup()` must rebuild every one of them. Add a test that checks every array's size equals `cars.size()` after `setup`, `reset` and `reset_racer`.
- Lifecycle test: oil a car, then call `reset`, `reset_racer`, finish and `queue_free` on the items node, and check that `item_grip_scale == 1.0` and that the visual child count goes back to the pickup count.
- CPU auto-activation of defensive items must still require `available()`, or finished cars will drop hazards on the track.
