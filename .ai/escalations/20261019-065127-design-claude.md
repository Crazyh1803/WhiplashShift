**Recommendation:** make `CourseCues` a pure `RefCounted` with `static func build(course: CourseDefinition) -> CourseCues`. The race scene builds it once per course load and passes the same instance to the boards and the HUD. Don't keep a static or global cache keyed by course, because tests call `configure()` again and a stale cache would go unnoticed. Don't write anything onto `CourseDefinition` either, since one of the plan's acceptance tests is that the course is not mutated.

**Data contract** (per cue, sorted by `distance`, no duplicates):
```
{ index:int,      # first point of the new meaningful surface
  distance:float, # _cumulative[index], in [0, total_length)
  from:int, to:int,      # Surfaces.Id; neither is RUMBLE, from != to
  end:String,     # "A"/"B", or "" = hold current end (ICE/OIL)
  low_grip:bool,  # to in {ICE, OIL}
  label:String }  # Surfaces.NAMES[to] + advice
func next_cue(route_pos: float) -> Dictionary   # {} if no cues
func metres_to(cue, route_pos) -> float         # fposmod(cue.distance - route_pos, total_length)
```
Rules for deriving cues:
- Point `i`'s `"s"` covers the segment from `i` to `i+1` (`dist` is measured that way, `track_data.gd:75`), so a boundary sits at `_cumulative[i]` wherever `s[i-1] != s[i]`.
- Rumble collapses into the surrounding surfaces. Tarmac→rumble→gravel gives one cue, tarmac→gravel, at the start of the gravel. Tarmac→rumble→tarmac gives no cue.
- `end` uses the same logic as `cpu_driver.gd:146-151`. Pull that ICE/OIL rule into one shared static, e.g. `Surfaces.advised_end(sid, current)`, without changing its behaviour, so the HUD and the CPU can't drift apart.

**HUD gating:**
- Show the cue when `metres_to <= maxf(MIN_M, speed * LEAD_S)`.
- Hide it when `progress.wrong_way` is set, or when `off_line >= w * 0.65`. That second check has to match `track_progress.gd:77`, because off the ribbon `progress.distance` stops updating and the cue would be stale.

**Edge-case tests:**
1. **Seam:**
   - The real course, or a synthetic one where `s[n-1] != s[0]`, must produce a cue at distance 0.
   - At `route_pos = total_length - 5`, `next_cue` returns that cue and `metres_to` is about 5.
   - When `s[n-1] == s[0]`, there's no cue at 0 and the surface run that spans the seam stays one run.
2. **Rumble collapse:** both of the patterns above, plus a course whose only surfaces are tarmac and rumble, which should give no cues.
3. **Single-surface course:** no cues, `next_cue` returns `{}`, and the HUD stays hidden without errors.
4. **ICE/OIL:** `end == ""`, `low_grip` is true, and for each cue `Surfaces.advised_end(...)` matches what `cpu_driver._preferred` would pick.
5. **Off-course and wrong-way:** drive a `TrackProgress` with synthetic positions. The HUD is hidden once `off_line` passes the threshold and once `wrong_way` is set, and it comes back after `recover()`.
6. **No mutation:** take a deep copy of `course.points`, `total_length` and `checkpoints` before `build`, then compare afterwards.
7. **Board facing:** for each board, its readable face (`basis.z` for Label3D/quad) has a dot product below -0.9 with the route `dir` at its point.
8. **Board back:** set `Label3D.double_sided = false`, or put an opaque backer behind it. The default is `true`, so wrong-way drivers would see mirrored text. Assert this in the test.
9. **Board clearance:**
   - Check against *every* centreline segment, not just the nearest one, because the course doubles back on itself. Lateral distance must be at least `w/2` plus the rail offset plus a margin.
   - Take the rail offset from track_builder; don't copy it in as a new constant.
   - Boards and their children contain no `CollisionObject3D`.
10. **Close boundaries:** when two cues are nearer than the board lead distance, place the boards at clamped positions in the right order, or merge them. They must not overlap, and no board may land before the previous boundary.

**Main tradeoff:** passing an instance around adds wiring, but there's nothing to invalidate. The one alternative worth considering is storing the cues as derived data in `CourseDefinition._rebuild_derived_data()`, next to `checkpoints`. That fits the resource's own "derived race metadata" comment and gives a single source, but it touches a file that physics and the CPU share and blurs the no-mutation test.

**Risks:**
- Extracting the shared end-advice function has to keep `_preferred` returning exactly what it does now; add a test that pins this.
- If boards are child nodes of the track, `track_builder` must not treat them as surface or rail geometry.
- Moving `"s"` to "the surface at a point" instead of "the surface of the segment after it" would shift every cue by one segment, so pin that convention in a test.
