**Root cause:** `godot/scripts/vehicle_bodywork.gd:156-160` and `:176-179` together cause the growth. I traced this from reading the code; I did not run it.

- For a `ShaderMaterial` (legacy `LIVERY_SHADER`), `_detach` only calls `_strip_wear(current)`. The clone stays installed on the surface and keeps `META_ORIGINAL`, which points at the previous original.
- On the next `_attach`, `current` is that stripped clone. `_chain_has_wear(current)` is false, so line 158 duplicates it again.
- Line 159 then overwrites `META_ORIGINAL` with `current`, the previous clone. The chain becomes `clone_n → clone_{n-1} → … → original0`. Each clone is held by the next clone's metadata, so one material is retained per damage cycle.
- The `BaseMaterial3D` path doesn't have this problem. `_detach` restores `original` and drops the clone.
- The `Resource.duplicate` metadata copy doesn't change the outcome, because line 159 overwrites it anyway.

**Fix:** reuse the existing private clone when it already carries `META_ORIGINAL` and is a `ShaderMaterial`. Re-append the wear pass at the tail of its `next_pass` chain instead of cloning again. A repaint by `Vehicle` installs a fresh material with no meta, so it still takes the clone path, and `META_ORIGINAL` is not changed. The seven production cars use `BaseMaterial3D` and are untouched.
