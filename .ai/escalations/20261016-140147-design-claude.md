**Recommendation:** build a small `deadbolt_blueprint_vehicle.gd` rig subclass, modelled on `blackjack_blueprint_vehicle.gd`, plus a 6-line hook in `wheel.gd`. Your plan holds up, with three corrections:

1. **Rotation is config only.** Set `"rotation_degrees": Vector3(0, 90, 0)` in the Deadbolt visual spec; `vehicle.gd:118` already applies it. A Blender (x,y,z) point ends up at Godot (−y, z, −x), so Blender +X lands on −Z (End A). Add a test asserting that the Coupe meshes' AABB centre has z < 0.
2. **Hiding the embedded wheels is already free.** `vehicle.gd:163-167` hides any mesh with "wheel/rim/tire" in its name. Every wheel mesh is named `Wheel_{Coupe,Truck}_*`, and no body mesh hits a false match (I checked for things like "Trim").
3. **Paint needs an override; you don't get it for free.** For any `vehicle_id != "blackjack"`, `vehicle.gd:189` paints *every* non-wheel surface with `_mat(vehicle_color)`, which wipes out glass, rubber and metal. In the subclass, call `super`, then go through each surface:
   - `Deadbolt_Paint` gets the primary colour, `Deadbolt_Secondary` the secondary, `Deadbolt_Stripe` the accent (each a duplicated source material).
   - Everything else gets `set_surface_override_material(i, null)`, which restores the authored material.

**Copying the wheels:** add to `wheel.gd`:
```gdscript
func set_visual_node(node: Node3D) -> void:
	if _visual != null:
		remove_child(_visual)
		_visual.free()
	_visual = node
	_visual_offset = Vector3.ZERO
	_visual_base_rotation = Vector3.ZERO
	add_child(node)
	_place_visual(ride_distance)
```
You need this because the placeholder sets `_visual_base_rotation.z = 90°` (`wheel.gd:165`). Copied meshes parented under it would come out rolled sideways.

In the subclass, after `super._build_wheels()` / `_refresh_wheel_visuals_and_mounts()`, do this for each `Wheel`:
- Pick the group by position, not by the `±1` in the name. Take the group whose AABB centre in vehicle space has the same sign of x and z as the wheel's hardpoint. Under the +90 yaw, Blender `+1` maps to Godot −X (L), so trusting the name gets the sides backwards.
- Duplicate the group's meshes, set `visible=true`, and give them `transform = wheel.global_transform.affine_inverse() * mesh.global_transform`.
- Subtract the group's hub centre so the hub sits at the holder's origin. `_place_visual` treats the origin as the axle (`wheel.gd:221`).
- Name the holder `ModularWheelVisual` so the base axle and visual code that look for it keep working.

**What stays as it is:** don't put `wheel_mounts`, `collision_boxes` or radii in the Deadbolt spec. `VISUAL_DEFAULTS` (`vehicle_catalog.gd:138`) then supplies the ±0.9/±1.6 hardpoints and the three-box collision. Inertia comes from `tuning` (`vehicle.gd:280`), so it's unaffected.

**Risks**
- **Wheels may not line up with the arches.** The GLB is 5.16 m long, but the physics wheelbase is 3.2 m and the track 1.8 m. Copied wheels sitting on the hardpoints probably won't line up with the arches. Fix it the Blackjack way: per-end visual `offset`/`scale` on the body, or a per-wheel visual offset. Never touch `wheel_mounts`, which moves the physics hardpoints. Tire radius ≠ `tuning.wheel_radius` causes floating or sinking; correct the y-offset by the radius difference, like `blackjack_blueprint_vehicle.gd:79`.
- **Collision overhang.** The body overhangs the default collision length by about 0.3 m at each end. That's OK for visual-only work, but mention it in the report.
- **The catalog points at missing files.** It references `deadbolt.glb` and `wheel_a/b.glb` (`vehicle_catalog.gd:127-129`); none of them exist. Point `scene` at `deadbolt_blueprint.glb` and drop the wheel scenes.
- **Customization rebuilds must recreate the copies.** `_rebuild_visuals` frees `VisualRoot`. Copy the wheels from fresh meshes after every rebuild and don't keep references to the old ones.
- **Factory gating.** Dispatch the new rig through `vehicle_factory.gd` the same way as Blackjack's `visual.rig`.

**The one alternative worth considering:** in the asset lane, export `wheel_coupe.glb` and `wheel_truck.glb` hub-centred, and use the existing `wheel_scene_a/b` path with no wheel code at all. It's cleaner over time, but it changes art, which this plan rules out. Do it later.
