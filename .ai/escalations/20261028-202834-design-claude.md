# Design recommendation: City GLB kit and first-quarter dressing

**Approach:** each asset is one GLB holding one mesh with up to 8 surfaces. A JSON manifest sits next to the GLBs. Godot pulls the `Mesh` out of each GLB and uses one MultiMesh per asset. Placement in the district comes from a fixed, hand-ordered slot table keyed on **forward route distance** `s`. Nothing is scattered by RNG.

## GLB and manifest contract
- **Files and import:** `godot/assets/city/kit/<id>.glb` plus `city_kit_manifest.json`. GLBs already load fine in tests through `preload` (see `blackjack_blueprint_vehicle.gd:7`), so the import pipeline isn't a risk.
- **Axes:** export from Blender as +Z up, +Y front. The glTF exporter turns that into Godot +Y up and **−Z front** (the facade). Origin is the centre of the footprint at y=0. Units are metres, transforms applied, and no nodes besides the mesh: no collision, lights or cameras.
- **Manifest per asset:** `id`, `class` (landmark/building/prop), `tris`, `aabb` (min/max in Godot axes), `footprint` (XZ rectangle including cantilevers), `front_setback_m`, `surfaces` (an ordered list of semantic names), `reuse_worlds`, `budget_note`.
- **Semantic surfaces** (fixed names, ≤8): `steel`, `ceramic`, `cavity`, `machinery`, `sinew`, `glow_cyan`, `glow_amber`, `trim`. The Godot side maps names to its existing materials: `steel` → `FACADE_SHADER`, `ceramic` → `cream`/`ceramic`, glows → `_glow`, `sinew` → `TrackMaterials.flesh()`. That keeps night readability in emissive and shader surfaces, with no sun or ambient changes.
- **Triangle budgets:** landmarks ≤18k, buildings ≤8k, props ≤2k. The district total is ≤150k triangles including instancing.

## Godot loader and batching
- **Loader:** add a `CityKit.load(id)` that instantiates the GLB once, takes the first `MeshInstance3D.mesh`, frees the scene and caches the mesh. Never add GLB scenes to the tree; `meshes.size() <= 24` would break.
- **Batching:** one `MultiMeshInstance3D` per asset ID, under a new `CityKit` node. Landmarks are batches with one instance. Each batch carries metadata:
  - `city_transforms`, the same pattern as `city_scenery.gd:419`;
  - `city_local_aabb`, taken from the manifest.

  Set materials per surface with `set_surface_override_material`, not `material_override`.
- **Placement transform:** `Transform3D(_basis(dir) * Basis(UP, 0 if side>0 else PI), pos + _basis(dir)*Vector3(along, 0, side*(w/2 + RAIL_OFFSET + setback + depth/2)))`. Local +Z is the right-hand side, so the −Z facade faces the road on both sides.
- **Acceptance:** run every slot through `_accept`, using manifest-AABB corners instead of `UNIT_BOX`. Reject anything under `ROAD_CLEARANCE` 3.5 m; do not nudge it.
- **Light budget:** street lights (≤9) plus the crown (1) leave **≤2 new OmniLights** for the kit, so beacons go through emissive surfaces. Draw calls: ≤14 kit batches and ≤64 surface draws in total.

## Removing only the opening placeholders
- Let `Q = total * 0.25` (about 520 m). That covers the 400 m boulevard plus about 120 m of the 204 m sweeper, so the gravel decks (from about 790 m) are untouched.
- **In `_towers`:** keep every `rng` draw exactly as it is today and skip only the `_accept` call when `fposmod(raw, total) < Q`. If you skip the draws instead, the random sequence shifts and every later tower moves.
- Towers at raw −100..0 sit in the last quarter. They stay, which keeps behind-grid readability.
- **Crown:** before the district is placed, add the crown's 96×96 area to `footprints`. Right now it isn't registered (`city_scenery.gd:319-337`), and it sits at about 480–610 m ahead, next to the sweeper exit.
- **Street walls/posts:** keep them. The test `nearest_wall < 12` (`block_circuit_tests.gd:226`) depends on them.
- **Kit slots:** require `s` in [8, Q − footprint_half] and also require every footprint corner's nearest route sample to fall in [0, Q). That handles corner cantilevers.

## Reverse races
`build_scenery` already passes `course.geometry()` (`course_catalog.gd:40`), which is the forward base. As long as the kit reads only `geometry` and never `is_reverse`, the district stays put. Add a test that `_signature` is equal for forward and reverse builds.

## Test compatibility (lead edits needed)
1. `:191`: batches ≤12 now fails (10 legacy + kit). Split it: legacy ≤12 excluding `CityKit`, plus kit ≤14.
2. `:206`: change the hard-coded unit box to `batch.get_meta("city_local_aabb", UNIT)`. Separately, assert that `multimesh.mesh.get_aabb()` is within 0.05 m of the manifest bounds.
3. `:235`: the opening Body count ≥12 will fail. Count kit instances with `s < Q` (≥20, ≥3 landmarks) and assert zero Body instances with `s` in [0, Q).
4. Add tests for: manifest triangle and surface limits; the kit having no instances with `s ≥ Q`; later Body transforms matching a baseline that has the gate off (filtered to `s ≥ Q`); and forward/reverse signature equality.

Nothing else changes: collision, lights, instance count 300–4500, clearance and determinism all hold if the kit records follow the existing metadata pattern.

## Main tradeoff
A per-asset MultiMesh means a landmark used once still pays for a batch, in exchange for one uniform test path. The alternative worth considering is `MeshInstance3D` for the 3 landmarks; that keeps the batch count lower but uses up the 24-mesh budget, since the crown already takes about 13.

**Risks:** the multi-surface GLB loses its materials if anyone uses `material_override`. Facade glow that leans on fog will vanish past 280 m unless far-layer surfaces set `disable_fog`.
