Checked the TrackProgress, CPU driver and test code; writing up the design now.

## Recommendation
Add a `RaceDirector` Node that **derives all race rules from `TrackProgress.total_distance`**, not from `progress.lap`. Add one fix to `TrackProgress.recover`. Leave the CPU driving logic alone.

### 1. Ranking and finish come from one value
- `abs_progress = total_distance + start_cum`, where `start_cum` is the cumulative distance at the car's grid point.
- **Grid behind the line:** each slot sits exactly on a centreline point found by walking back from index 0: slot k is about `8 + 7k` m behind, and only the lane offset changes sideways. A car then starts at about `start_cum ≈ L - gap`.
- **Finish:** `abs_progress >= 4·L`. Every car crosses the line once to start, then completes three full laps, whatever its slot. No spawn offset can shorten the first lap.
- **Displayed lap:** `clamp(floor((abs_progress - L)/L) + 2, 1, 3)`.
- **Order:** finished cars come first, in the order they were appended. That array is append-only and holds `{car, time}`. Unfinished cars follow, sorted by `abs_progress` descending, with grid index breaking ties. If several cars finish in the same physics frame, sort them by overshoot, then grid index, before appending.
- Don't use `progress.lap`. A behind-line start makes the first seam crossing silently fail the `_lap_travel > 0.9L` check, and the code at `track_progress.gd:77` gives no clear rule for that case.

### 2. Recovery currently inflates progress
`recover()` (`track_progress.gd:34`) moves `distance` back to the checkpoint but keeps `total_distance`. Driving that stretch again counts it twice. The existing test at `cpu_tests.gd:109` only checks right after recovery, so it doesn't catch this.
```diff
 func recover(start_index: int) -> void:
+	var target := posmod(start_index, course.points.size())
+	var back := maxf(0.0, wrapf(distance - _cumulative[target], -course.total_length * 0.5, course.total_length * 0.5))
+	total_distance -= back
+	_lap_travel = maxf(0.0, _lap_travel - back)
-	index = posmod(start_index, course.points.size())
+	index = target
```
A forward jump subtracts 0, so the "cannot add lap or distance" test at `cpu_tests.gd:67` still passes. Add a test: recover, drive back to the old point, and assert that `total_distance` matches what it was before recovery.

### 3. States and locks
The states are COUNTDOWN, RACING and RESULTS. The director owns the player's TrackProgress. Set `process_physics_priority = 100` so it runs after the drivers and after the player-input code.
- **Countdown:** don't freeze the cars. Spawn lift would leave them hovering, and they'd drop at GO. Instead set `driver.enabled = false` and have the player input in `proving_ground._physics_process` write `throttle 0, brake 1`.
- **Finishing (CPU and player):** call `retire(car)`: zero the controls, `freeze = true`, and set `collision_layer` and `collision_mask` to 0. Freeze alone (static mode) still collides. Also remove the car from every `driver.peers`, or the CPUs will brake for a ghost. `enabled = false` doesn't zero the controls (`cpu_driver.gd:42`), so `retire` has to.
- **Retiring the player too** stops a parked player from blocking CPUs at the line.
- **Input gating:**
  - R: player-only checkpoint recovery, and only while RACING and the player hasn't finished. Today R resets the whole field.
  - Space: only while RACING.
  - F2: only while RACING, and never re-enables a retired car.
  - Enter: retry, only in RESULTS.
  - Set `focus_mode = FOCUS_NONE` on the HUD buttons, or Enter fires twice (button plus key) and reloads twice.
- **Retry:** write the roster in use back to `GameSession.cpu_vehicle_ids`, then call `reload_current_scene()`. Otherwise `random_cpu_roster` (`proving_ground.gd:97`) picks a new roster.

### 4. Test compatibility, the main risk
`cpu_tests` runs for 420 s. With the director in place, the CPUs finish after three laps and get retired. `_test_recovery` then never triggers, because tick exits early when disabled. In the fixture: wait until `director.state == RACING`, then call `director.set_physics_process(false)` to free-run without finish handling. `consolidation_visual_qa.gd:45` calls `race._respawn()`, so keep that name, and have it place the player on their grid slot.

### Tradeoff and alternative
Reloading the scene for retry is simple and leaves no stale state, but it costs a scene load. The alternative is an in-place `director.restart()`, which is faster but has to reset vehicle, driver, HUD and audio state. Only switch to it if the reload is noticeably slow.

**Other risks:** HUD line 68 reads `progress.lap` and has to switch to director data. With the ±35-point search window and the 100 m jump guard, a cut across a hairpin is only blocked by the off-line check (`0.65·w`). Confirm that no hairpin on this course comes within that distance of itself.
