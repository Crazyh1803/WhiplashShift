**Recommendation: a runtime "frontage-slice" derivation in `CityRealismCatalog`, paid for by a compact sidewalk strip.**

**Why the current approach can't reach 24**
- A full-detail building costs about 16–19k tris (`habitation_workshop` is 18,704). Adding 24 of them means about 430k tris.
- Global headroom is 12.5k. Even removing every sidewalk panel (253 × 1108 ≈ 280k) only brings that to about 292k.
- Quarter headroom is [8.2k, 19.7k, 40.5k, 3.9k]. Q3 is effectively full.
- So full-detail clones are ruled out by the numbers. Each new building has to come in around 6–8k.

**1. Free the sidewalk geometry (about 50k per quarter)**
- `sidewalk_panel` is authored at 6×4 m, then stretched to 16.1×5.5 by `city_realism_layout.gd:82`. That's a 2.7× smear, so its 1108 tris aren't buying any fidelity.
- Have the asset lead author an additional `sidewalk_strip.glb` with `ak-blender`: native 16.1×5.5 m, at most about 250 tris, using only the existing `concrete`/`cladding_patch` library materials. No new textures.
- Load it the way `_load_ground` does: optional, validated against an AABB contract and a tris cap. If it's missing, fall back to `sidewalk_panel`. `sidewalk_panel.glb` stays untouched.
- `_ground` uses the strip only when `ground_enabled`.
- Expected saving: 253 × ~850 ≈ 215k globally, about 54k per quarter.

**2. Derive compact detailed buildings at load time (no new GLBs)**
In `_load_mesh`, add a filtered variant using the existing SurfaceTool loop with triangle-centroid predicates, and cache it as e.g. `podium:<family>` with its cost from `count_triangles`:
- **Composition A, "shop row":** keep triangles from the full GLB with centroid z < 4 m (the street face) and y < 6 m (shopfront, shutters, awnings, signs). Close the massing behind with the matching `@far` LOD1 mesh cropped to z ≥ 4 or y ≥ 6. That gives a one- to two-storey detailed workshop row.
- **Composition B, "walk-up":** the same ground-storey front slice from family A, with family B's LOD1 upper floors stacked above it. Visibly different from any original.
- Both use only shared materials. Within a chunk they add few or no new surfaces, which matters because the window is at 113/160.
- Give them no light or entrance records, so the 12-light cap (`city_scenery.gd:8`) is unaffected.
- Place them with a gap-fill pass at offsets between the existing 64 stations. Reuse `_place`/`_try_add` unchanged so road clearance, solid overlap, curve and visible-window checks all still apply.
- Give them their own `@far` key (the LOD1 crop), because `_add_group` looks up `id+"@far"` for every building (`city_realism_layout.gd:177`).

**Main tradeoff**
The sidewalk gets re-authored, so it's a visual change to ground. In exchange, the 29 original buildings stay byte-identical.

**Alternative worth considering**
Lossless hidden-face culling (bottom faces, tile end-caps) on `sidewalk_panel` at load time. It keeps the exact look, but it probably saves under 30%, which isn't enough on its own. Measure it first; if it gets close to 900 tris per panel saved, prefer it.

**Risks**
- The slice seams at z=4 and y=6 may show gaps. Put the cut behind a cornice or awning line, or overlap it by 0.2 m.
- The derived meshes' AABB depth is shorter than the original, so recheck setback and footprint.
- The derived variants must be built after `materials` is populated, and must be excluded from the `FAMILIES` validation at `city_realism_catalog.gd:55`.
- Tests that assume 29 buildings, or that every building has lights or entrances, need explicit compact-role exemptions.
- Order the placement pass so originals are placed first and can't be crowded out.

**Testing**
`common.sh:19-27` gives the environment priority over `.agent.env`, and `.agent.env` already uses `${TEST_CMD:-…}`. `test_season.py` accepts `--scenes`. So:
- **Narrow lead runs:** `TEST_CMD='python tools/workflow/test_season.py --scenes <city_realism_tests> <city_backdrop_tests>' ak-test`
- **Delegation:** prefix the same assignment on the `ak-delegate claude …` call. The delegate's `ak-test` inherits it, so editing `.agent.env` isn't needed.
- **Before review and publish:** run `env -u TEST_CMD ak-test` so the full suite runs.
