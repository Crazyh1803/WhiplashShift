I couldn't run Godot here, so this patch is untested. I also can't prove the q3 and composition targets are reachable. The log tail cuts off the `DENSITY_COUNTS` line, which holds the infill rejection counts by reason. Read it before trusting the patch (see Verify).

## Root cause

- **Greedy fill:** `_infill` at `city_realism_layout.gd:90-122` walks `q0 s- → q0 s+ → q1 …` and places everything it can in each cell before moving on. Cells later in that order are starved by the shared limits. The 75k per-cell cap only softened this. It didn't make the order fair.
- **Visible budget:** the worst window reads 319838 of 320000 triangles and 147 of 160 surfaces. That is `_fits_visible` (`:307`), and q3 is only at 268k of 400k. So q3 is losing to the shared near-window budget or to geometry, not to the quarter budget.
- **Compositions:** each one needs 3 consecutive full-width parts (~45 m) to pass overlap, clearance, curve and visible checks together. Any single failure rolls back the whole group (`:143-145`). Nothing ever places one, which matches the empty `[]`.
- **Retry cost:** `_snapshot` (`:151`) deep-copies `rendering_groups` on every attempt, and `_try_add` runs the clearance test before the cheap budget test (`:263-266`).
