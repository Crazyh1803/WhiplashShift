**Root cause:** `cpu_tests.gd` is nondeterministic because it never seeds the CPU roster. The Knifeedge failure was not caused by this change.

**Evidence**
- `cpu_tests.gd:11-13` instantiates `proving_ground.tscn` without calling `GameSession.configure`.
- `GameSession.cpu_vehicle_ids` is therefore empty. `proving_ground.gd:95-97` falls back to `VehicleCatalog.random_cpu_roster(2, selected_id)`.
- That function (`vehicle_catalog.gd:222`) calls `candidates.shuffle()` on an unseeded RNG, so the two CPU cars change on every run.
- This run drew BOILERFANG and KNIFEEDGE. `.ai/last-test.log:91-93` shows KNIFEEDGE with `recoveries=1` at t=30 and `recoveries=3` at t=60, with `idx` stuck at 127/126. It is wedged on the course while BOILERFANG advances normally (idx 154 → 280 → 423, 0 recoveries).
- Nightshift was not in the roster, so its change cannot be the cause. In `HEAD~2..` the diff to the catalog and factory touches only the `nightshift` entry plus one new `elif` branch for `rig == "nightshift_blueprint"`. The `knifeedge` entry (`vehicle_catalog.gd:121-124`) and the `Vehicle` physics path are untouched.

**Pre-existing:** very likely yes. Knifeedge is a RAZORBUG on the plain `Vehicle` path, which this branch did not change, so it should fail the same way on `main`. Check this directly (see "Verify").

**Fix: test-only, and a fixed roster is appropriate.** Pin the CPU roster so the test is reproducible, and leave the random-roster behavior in the game alone. Set the roster before instantiating the scene, so it goes through the same `GameSession` path `proving_ground.gd` already reads. A fixed `[deadbolt, nightshift]` roster is reasonable because it exercises the authored-rig CPU path this branch adds.

The player's selected vehicle has to be known for the exclusion rule, so use `GameSession.selected_vehicle_id`. The existing assertion at line 22 requires the CPUs to share the player's tuning, so confirm that still holds with a nightshift CPU.

    _test_progress()
+   # Pin the roster; the default path shuffles via an unseeded RNG.

    var packed: PackedScene = load("res://scenes/proving_ground.tscn")

Also reset `GameSession.cpu_vehicle_ids = []` at the end of `_ready()`, before `quit`, so other tests in the same process don't inherit the pin.

**Do not** tweak the thresholds (`recoveries <= 4`, `lap >= 2`) to make Knifeedge pass. That would hide a real course-handling weakness.
