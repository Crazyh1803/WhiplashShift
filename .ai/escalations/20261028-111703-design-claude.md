**Recommendation: keep one race scene and pick the course through a small catalog.**

Keep `proving_ground.gd` as the only race scene. Add a new `scripts/course_catalog.gd` that maps `course_id` to a layout record:

```
{ "build": Callable -> CourseDefinition, "start_offset": int,
  "grid": Array[int], "scenery": Callable(parent, course), "proving_ground": bool }
```

- `split_shift` returns exactly what the scene does today: offset `16`, grid `[n-14, n-4, n-9]`, `TrackScenery.build` plus guidance, deposits and the proving ground.
- `block_circuit` lives in new files: `block_circuit_data.gd` and `city_scenery.gd`.
- `GameSession` gets `course_id := "split_shift"`, cleaned against the catalog the same way `set_cpu_difficulty` cleans its value.
- The garage adds one OptionButton and saves the choice as a `profile/course` key in its existing ConfigFile (`garage.gd:49`). That is a new key, not a new save format.
- In `proving_ground.gd`, replace the hardcoded values (`:79` `slice(16)`, `:90` proving ground, `:84-86` scenery, `:115` grid) with catalog lookups. Nothing else in that file should change.

**Main tradeoff:** the scene changes slightly. The alternative is a separate `city_circuit.tscn`, which leaves Split Shift's scene untouched but copies about 380 lines of race, retry and retire logic that would then drift apart. Choose the catalog.

**Layout authoring pitfalls**
- Reuse `TrackData._straight/_arc` (tests already call them). The code at the end of `author()` that turns nodes into points is hard-wired to `CENTRE`. Either move it into a `TrackData.finalize(nodes, centre)` and check it against `terrain_baseline.gd`, or copy it.
- Author the start line at point 0 so `start_offset = 0`. The last 20 or more points (at least 70 m) must be one straight tarmac run. The grid sits up to 14 points (49 m) behind the line, and the CPUs run `lane_offset ±4`. A width of 26 matches Split Shift; anything under 18 puts CPU spawns on the rail.
- Stay out of the proving-ground box (x −642 to −420, |z| < 230+r, `track_scenery.gd:130`), or set `proving_ground: false` for City and skip that check. Keep the layout within ±1900 of the 4000 m ground.
- For non-adjacent segments (index gap greater than about 2w/STEP), the centreline gap must be at least (wa+wb)/2 + 2×`RAIL_OFFSET` + 3. The guard rails have collision, so parallel boulevards whose rails touch create a wall.
- Keep the arc radius at 25 m or more in the service district. The CPU looks ahead `10 + speed*0.7` (`cpu_driver.gd:132`), so a tight hairpin points it across the infield.
- Surface runs should be 40 m or longer so CPU swap lead and corner cues have room to work.
- Mud and gravel get default relief. Author no `relief` configs in this slice.

**Scenery clearance pitfalls**
- `_prop` checks only the root origin plus its radius. Child boxes, ribs and cantilevers can reach into the road. Test the global AABB of every `MeshInstance3D` under the City root against the road envelope. For a clear overhead corridor, reject any AABB whose XZ footprint overlaps an envelope, at any height.
- `clear_of_course` takes the larger width of each segment and runs O(props × points), so batch MultiMesh transforms rather than creating many props.
- Add no StaticBody or CollisionShape under the scenery root, and assert that in a test.
- Lights are expensive: give City a fixed budget, such as 12 or fewer shadowless OmniLights.

**CPU and start-grid constraints**
- Grid indices must come before index 0 in loop order. Then `TrackProgress.setup(course, gridIdx)` starts behind the line and the first crossing does not count as a lap.
- Checkpoints are fixed at 110 m (`course_definition.gd:9`), so expect about `length/110` of them. Recovery uses `checkpoint_index`, so no checkpoint point may sit in a corner apex where the facing direction is ambiguous.

**Testing**
1. Every catalog id passes `validate()`. A Split Shift golden test checks that point count, `total_length`, checkpoint count and grid transforms are unchanged.
2. Block Circuit geometry: no envelope intersections, the grid straight is long and wide enough, and the course is clear of the proving ground.
3. City scenery: AABB clearance against the envelope, zero collision bodies, and the props are deterministic for a given seed.
4. Scene smoke for each course: load the race with each `GameSession.course_id`, teleport the player through checkpoints for 3 laps, reach RESULTS, call `restart_race`, and check that lap and grid state reset.
5. CPU smoke on Block Circuit: run about 60 s of physics. Each CPU should gain at least 300 m of progress, spend no more than 2 s wrong-way, and not recover repeatedly.
6. A garage test that the course option round-trips through the profile and that an unknown id falls back to `split_shift`.

**Risks to existing systems:** existing tests build courses through `TrackData.build_course()`, and `track_visual_tests.gd:24` copies the `slice(16)` rotation. Leave both untouched so the catalog adds Block Circuit without changing Split Shift's behaviour.
