**Recommendation: the approach is sound. Keep the three `ColorPickerButton`s as the single source of truth, layer swatches on top for Blackjack only, and put everything new in task-owned files so `garage.gd` gets only a small hook.**

### Swatch control
- **Hook:** build a 12-button row per channel next to each picker. A swatch press sets `picker.color` and then calls `_commit_customization()` explicitly, because assigning `.color` in code does not emit `color_changed` (`garage.gd:304`).
- **Gating:** in `_load_customization_controls()` (`garage.gd:450`), toggle `picker.visible` against swatch-row visibility on `vehicle_id == "blackjack"`. Other vehicles keep the untouched picker.
- **Legacy colours:** `_commit_customization()` (`garage.gd:491-494`) keeps reading the pickers, so a saved off-palette hex stays in the hidden picker and is rewritten unchanged when another channel, wheel or part changes. No change to `GameSession` or the save schema.
- **Highlighting:** highlight a swatch only on an exact `to_html(false)` match. For no match, show a non-interactive "CUSTOM #hex" chip, and never snap to the nearest swatch.
- **Palette:** store it as lowercase 6-digit hex so it is stable through `_sanitize_customization` (`game_session.gd:55`).

### Studio environment
- **Shape:** a new static factory (e.g. `scripts/studio_environment.gd`) that caches one procedural `Sky` and returns a new `Environment` per caller.
- **Why not share the `Environment`:** the QA script mutates its SSAO settings (`blackjack_blueprint_visual_qa.gd:7-9`), and the two backgrounds differ (`091117` in the garage, `55616b` in QA).
- **Settings:** keep `BG_COLOR`; set `ambient_light_source` and `reflected_light_source` to SKY, lower ambient energy to compensate, and set the AgX tonemap in the factory. The garage is currently linear, so garage and QA captures don't match today.
- **Radiance:** use `Sky.PROCESS_MODE_QUALITY`. The garage capture waits only 4 frames (`blackjack_blueprint_visual_qa.gd:77`), and incremental or realtime radiance would be captured half-converged.

### Clearcoat isolation
- **Leave the material code alone.** The `Paint_*` gate and per-surface duplicate already exist (`vehicle.gd:204-215`, `blackjack_blueprint_vehicle.gd:225-233`).
- **Keep the current values.** `_has_automotive_coating` pins metallic .28, roughness .32, clearcoat .5 and clearcoat roughness .16 (`blackjack_blueprint_tests.gd:227`). The flat look comes from `AMBIENT_SOURCE_COLOR` giving nothing to reflect, so the environment is the fix.

### Main tradeoff
A sky reflection source is global to the viewport. Protected Glass, Mirror, Gunmetal and BrushedMetal will also pick up reflections. Their materials and overrides are untouched, so the tests hold, but every visual baseline shifts and needs re-capturing and re-approval.

### Alternative
A `ReflectionProbe` on a dedicated cull layer (paint meshes are already on layer 2, `blackjack_blueprint_vehicle.gd:215`) would confine reflections to paint. It costs more setup, and unreflective chrome and glass next to glossy paint would look wrong.

### Risks
- **Commit scope conflict:** the plan says not to commit the user's pending garage files, but the hook must live in `garage.gd`. Put the palette, widget and environment in new files, keep the `garage.gd` change to about 15 additive lines, and report it as an uncommitted hunk. The file is untracked, so snapshot it first; git cannot restore it.
- **Names the QA depends on:** keep `_preview_viewport`, `_preview_camera`, `_customization_popup` and `_refresh_customization_preview` (`blackjack_blueprint_visual_qa.gd:67-72`).
- **Shared world:** the preview `SubViewport` does not set `own_world_3d` (`garage.gd:357`); only the QA forces it. Set it at creation so the studio sky cannot leak into, or collide with, another `WorldEnvironment`.
- **Out of scope:** leave `proving_ground.gd:38-44` alone; it is gameplay sky and a user-modified file.
