**Diagnosis**

The root cause is `_update_visual_bogie` (`vehicle.gd:397-408`). It sets `_bogie_root.position.y` to the mean of the rear pair's `ModularWheelVisual.position.y`. That value is `-(ride_distance - radius) + assembly_offset`, which is the body-local ground height at the rear hardpoint z (`half_base`). The bogie sits at `middle_bogie_z` (0.66, `vehicle.gd:366`), not at the rear z.

When the chassis has a static rake or pitch, the ground plane in body space is tilted. Its height at z=0.66 differs from the height at the rear axle by about `(half_base - 0.66)·tan(pitch)`. I haven't read `half_base`. The code comment at `vehicle.gd:805` cites a 5° rake. If `half_base` is about 1.5 m, that is about 0.84 × 0.087 ≈ 7 cm. That fits "slightly through the ground". The wheels' radii don't affect this, because the child wheels use `ride_distance = radius` from `setup()` and never cast.

This is a hypothesis from reading the code. I haven't run it.

A purely visual, opt-in offset is appropriate:
- The bogie wheels aren't in `wheels`, so they have no raycast, no force, and no inertia contribution.
- The patch only changes `_bogie_root.position.y`, which is a visual node.
- Mass, suspension, steering and the four hardpoints are untouched.

**Proposed fix**

Place the bogie at the ground height linearly interpolated, in body space, between the front and rear pair contact heights at `bogie_z`. The flag is off by default, so existing vehicles behave as before.

```diff
--- a/godot/scripts/vehicle.gd
+++ b/godot/scripts/vehicle.gd
@@ func _update_visual_bogie() -> void:
 	var pair := _wheel_pair("B")
 	if pair.size() != 2:
 		return
+	if bool(_visual_config.get("middle_bogie_follow_ground", false)):
+		var front := _wheel_pair("A")
+		if front.size() == 2:
+			var bogie_z := float(_visual_config.get("middle_bogie_z", 0.66))
+			var z_a := (front[0].position.z + front[1].position.z) * 0.5
+			var z_b := (pair[0].position.z + pair[1].position.z) * 0.5
+			var contact_a := 0.0
+			var contact_b := 0.0
+			for i: int in 2:
+				contact_a += (front[i].position.y - front[i].ride_distance) * 0.5
+				contact_b += (pair[i].position.y - pair[i].ride_distance) * 0.5

+			# Bogie hardpoint is y=0 and its wheels sit at ride_distance == radius.
+			_bogie_root.position.y = lerpf(contact_a, contact_b, t) + tuning.wheel_radius("B")
+			return
 	var ride_y := 0.0
 	for wheel: Wheel in pair:
```

**Caveat**

The interpolation assumes the ground is a plane across the wheelbase. On a rugged bump between the axles, the bogie can still clip by roughly the bump height. For static QA and normal driving this is fine, and the alternative is a third raycast, which would add a physics query. If you see clipping on rough terrain, clamp `_bogie_root.position.y` to be no lower than the lower of the two pair contacts. I'd leave that out until a real case shows it.
